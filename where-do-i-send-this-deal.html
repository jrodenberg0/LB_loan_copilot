Credit Box RAG · IP Loan Exchange

Where do I send this deal?

The Master Credit Box already answers this — it's just buried across 16 spreadsheets, 78 lender names, and one analyst's memory. Four people touch it every week. Here's what changes for each of them.

Today: one 23,000-cell workbook is the entire lending playbook — routing rules, rate grids, underwriting quirks, even portal passwords, all in merged cells and freeform text. The system being built turns that workbook into a queryable ontology: lenders, products, and scenarios as linked records, reasoned over instead of searched.

The question that started this

640 FICO, $90k property in Baltimore, 1 prior flip — where do I send this?

The Analyst

Quinton · maintains the box

Every rate change goes through me, by hand, in a workbook with my name nowhere on it.

Today

A lender emails a new rate sheet. Quinton finds the right cell across merged headers and freeform narrative, edits it directly, and hopes nothing downstream depended on the old value.

No diff, no audit trail, no one else can safely make the change.

Tomorrow

Compliance

Guards what shouldn't leak

Somewhere in that workbook is a plaintext password sitting two rows below a rate grid.

Today

Every product sheet carries User Name / Password rows for lender portals, in the same cells as public rate data, with no access control between the two.

Tomorrow

Credential rows are extracted and flagged sensitive: true at parse time. The RAG query layer omits them by default; the vault marks them #sensitive and restricts read access.

sensitive: true quarantined by default

What has to hold for this to be trustworthy

01

Every answer traces to a row. No synthesized rate that can't be pointed back to a sheet, a cell, a date.

02

Confidence is visible, not implied. Typed, text, manual, inferred — the broker sees which kind of answer they got.

03

Updates are a form, not an edit. The YAML template is the only way in, so every change is diffed and attributed before it lands.
